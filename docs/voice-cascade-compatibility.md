## 4. Supported streaming and turn outline

### Sarvam realtime STT

R18 public `sarvam.STTRealtime` is keyword-only: `language`, `stream_type`, `mode`, `endpointing`, `encoding`, `sample_rate`, `prompt`, `return_timestamps`, `api_key`, `base_url`, `http_session`, and four `vad_*` tuning parameters.
Proposed settings for validation: `language="auto"`, `mode="codemix"`, `stream_type="balanced"`, `endpointing="vad"`, `encoding="linear16"`, `sample_rate=16000`; leave VAD tuning at provider defaults initially (SDD §§4/6).
Pinned model is **`saaras:v3-realtime`**, not a constructor choice; socket is `wss://api.sarvam.ai/speech-to-text-realtime/ws`. It accepts 8/16 kHz mono and chunks audio through the plugin, without the native Google PCM wrapper.
The key comes from `api_key` or `SARVAM_API_KEY`; socket authentication uses the subscription-key header. A key/credit balance does not prove realtime entitlement; LiveKit's guide explicitly requires a subscription including realtime streaming access [D-STT].
R18 exposes streaming/interim capabilities; maps provider speech/partial/final events to `START_OF_SPEECH`, `INTERIM_TRANSCRIPT`, `FINAL_TRANSCRIPT`, `END_OF_SPEECH`, including terminal-utterance flushing before end.
Partials are provisional. Vendor docs distinguish codemix finals from partial transcription; final/turn ordering, silence, empty finals and interruption behavior require fake-transport checks [D-RT; R18].
`stream()` forces `max_retry=0`; socket failure does not reconnect the same stream. A newly created stream remains a new potentially billed admission, not automatic recovery (R18; SDD §§4/6/8).
Stream/component `aclose()` closes tasks/streams and owned HTTP resources; local teardown does not establish provider termination, room deletion or a hard spending deadline.
`RECOGNITION_USAGE` supplies audio-duration deltas; server session-end duration tops up local reporting without double counting, with local duration fallback. This is usage evidence, not an invoice or proof that muted time is unmetered.
Provider docs now also list `saaras:v4` and v4-only keyterms; R18 fixes v3-realtime and does not expose that model switch. Treat this service/plugin capability difference explicitly; do not assume v4 support [D-RT].

### Ordinary Gemini text LLM

G18 public `google.LLM(model="gemini-3.1-flash-lite", vertexai=False, ...)` accepts a model string and `api_key` or `GOOGLE_API_KEY`; explicit `vertexai=False` avoids the alternate cloud-auth path.
The exact stable identifier **`gemini-3.1-flash-lite`** is documented for text output; its model page lists neither Live API nor audio generation support [D-GEM]. Sarvam supplies speech output.
Constructor default is `gemini-2.5-flash`; the pinned adapter docstring mentions an older default. Pass the researched model explicitly rather than trusting either default (G18).
Public `chat(chat_ctx=..., conn_options=...)` returns an async `LLMStream`; G18 calls `client.aio.models.generate_content_stream` and emits text deltas plus `CompletionUsage` for prompt/completion/cached/total tokens.
Adapter string acceptance plus vendor model documentation establishes plausibility, not a validated SDK/model pairing or this key's access/quota. No authenticated lookup was made.
Core LLMStream uses `APIConnectOptions.max_retry`; `aclose()` cancels its task and drains metrics; Google component `aclose()` closes the GenAI async client (L18/G18).
Underlying GenAI HTTP retry/cancellation and timeout interactions remain a separate offline check; framework max_retry=0 alone is not a proof of one HTTP attempt. `http_options` is exposed by G18.
G18 prewarming calls the model-list API. Later network denial must precede imports and all construction/start/prewarm paths; no such path was executed here.
Do not apply the native Google Live private reconnect/PCM wrappers to text calls. Multiple ordinary text turns are expected; additional retry usage must still be bounded/accounted (SDD §4).

### Sarvam streaming TTS

T18 public `sarvam.TTS` accepts `target_language_code`, `model`, `speaker`, `speech_sample_rate`, `num_channels`, `pace`, `temperature`, `output_audio_codec`, API key/session/URL options and buffering/completion options.
Proposed explicit stock configuration: `model="bulbul:v3"`, `speaker="shubh"`, `target_language_code="en-IN"`, `speech_sample_rate=24000`, `num_channels=1`, `output_audio_codec="mp3"`, `pace=1.0`; Hindi-dominant Hinglish with `hi-IN` needs separate quality evaluation.
T18 validates a supported explicit language; it does not expose STT-style `auto` language selection. Code-mixed recognition does not establish code-mixed synthesis quality, pronunciation, script choice or safe per-turn language switching (SDD §4).
Model/speaker mapping includes Bulbul v3 stock `shubh`; cloning is outside this record. Service cloning capability would not establish compatibility with this class.
The streaming path is `wss://api.sarvam.ai/text-to-speech/ws`, using the subscription-key header, text chunks, flush and completion messages. `stream()` returns `SynthesizeStream` with `push_text`, `flush`, `end_input` and async audio iteration (T18/Q18).
MP3 is the plugin wire default; supported codec mapping also includes linear16/WAV and other encoded formats. Its audio emitter decodes to mono RTC audio frames; output frame rate follows the configured sample rate.
**Default discrepancy:** plugin sample-rate default is 22050, while vendor Bulbul v3 docs specify 24000. Set 24000 explicitly. Vendor forbids v3 pitch/loudness and always preprocesses; streaming T18 sends those controls only for v2. General constructor options do not imply v3 control support [D-TTS; T18].
Framework retry options govern TTS synthesis attempts; stale pooled sockets can raise a retryable connection error. Start later tests with max_retry=0 and verify socket counts rather than claiming the native one-connection wrapper applies (Q18/T18).
Stream `aclose()` cancels stream tasks; component `aclose()` closes active streams and the connection pool. No documented provider cancellation acknowledgment establishes stopped billing or audible playback delivery.
`TTSMetrics` includes character count, generated audio duration, timing and cancellation; it is not an exact provider invoice or a delivery acknowledgment (Q18; SDD §§5/8).

### Shared AgentSession orchestration/startup

A18 accepts separate `stt`, ordinary `llm`, `tts`, `vad` and `SessionConnectOptions` objects. Proposed construction uses the components above, **`vad=None`**, and **`turn_handling={"turn_detection": "stt"}`**.
Explicit settings matter: omitted VAD selects the core inference VAD, and omitted turn strategy selects its default detector. STT mode is supported without a VAD object; Sarvam supplies speech boundaries (A18/V18). No additional turn-detector/VAD package is selected.
AgentSession connects STT finals/turn boundaries to chat generation, streams text through TTS, and owns playback/interruption sequencing. Reuse that supported pipeline; do not design a parallel audio loop (SDD §§3/5/6).
Core 1.8.3 introduces `turn_handling`; older `turn_detection`/interruption arguments are deprecated. Session `aclose()` exists in both installed 1.2.12 and A18, but argument/event semantics and cleanup ownership require cross-profile conformance.
Session `metrics_collected` is deprecated in A18 in favor of `session_usage_updated` and `ChatMessage.metrics`; component `metrics_collected`, transcript, state, error and close events remain useful interfaces, not permissions to persist content (A18/L18/Q18).
Google and Sarvam package imports register plugins; B18 rejects registration off the main thread. Sarvam import also loads its LLM adapter; Google imports realtime/cloud namespaces even for a text-only selection.
Later bootstrap must initialize/verify the selected registrations on the main thread before admission; this source review does not justify changing the proven native bootstrap or enabling hot reload (B18/I18/J18; SDD §6).
